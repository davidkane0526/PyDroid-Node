# 1.4.83 Deterministic Core

## Why this release exists

1.4.82 could report a green packaged smoke while Remote Web was unusable because the smoke verified a host-status bridge rather than proving that the packaged application had opened TCP 8765 and served its browser bundle. Earlier Phase 10 work also accumulated lifecycle generations, readiness probes, reconciliation polling, recovery loops, firewall/profile inspection and validation freeze gates around a service whose accepted behavior was fundamentally simple.

1.4.83 removes those alternate control paths. The design rule is now: **production code performs the requested operation once; tests observe the result; a failure stays a failure.**

## Remote Web production path

Desktop and Android follow the same contract:

1. `startServer()` binds `0.0.0.0:8765`.
2. The HTTP server immediately owns `/health`, the SPA shell/assets, pairing and authenticated APIs.
3. SSDP/UPnP/mDNS starts independently on a best-effort basis. Discovery failure does not close or reject HTTP.
4. A repeated normal UI start reuses the already-running server; there is no separate native lifecycle/status state machine.
5. `stopServer()` closes discovery and the HTTP listener directly.

Removed from the production path: loopback/LAN readiness self-probes, firewall profile/category state machines, route polling/watchers, lifecycle generations/futures/barriers, 3-second React reconciliation, network-change auto-recovery, per-protocol recovery attempts, PIN cooldown, token TTL/address binding, API rate limits and Remote production freeze hashes. **1.4.85 restores two narrow host-network responsibilities that 1.4.83 removed too aggressively:** Desktop ensures the three fixed Windows inbound rules for TCP 8765 / UDP 1900 / UDP 5353 when the user explicitly starts the service, and performs one default-IPv4-route lookup to choose the advertised LAN URL. These operations do not inspect Public/Private network category, self-probe HTTP, poll, retry, recover, or participate in diagnostics.

Retained deliberately: fixed port 8765, short LAN URL, PIN/token pairing semantics, packaged browser assets, HTTP request size/path checks, socket/execution timeouts, SSDP/UPnP/mDNS protocol implementation. These are direct protocol/product semantics, not recovery paths.

## Validation contract

A Remote test is only meaningful when it uses the real listener.

- `scripts/remote-host-e2e-smoke.mjs` starts the production Desktop service, performs real HTTP on 8765, pairs, calls an authenticated API, validates UPnP, and sends SSDP M-SEARCH.
- `scripts/android-remote-host-jvm-smoke.mjs` compiles the real Android server/service with minimal platform stubs, opens 8765, requests `/health`, `/`, and the real JS asset, then verifies stop releases the port.
- The packaged Electron smoke calls `startRemoteServer(true)` and performs live HTTP requests to `/health`, `/`, and the packaged JS asset before it may report success.
- In-app automated diagnostics do not start/stop Remote Web and therefore cannot perturb or falsely certify its production lifecycle.

No same-host test can prove that a second physical machine traverses an operating-system firewall. That external boundary remains a real-device acceptance check, but local/package tests can no longer pass without an actual listening/serving host.

## Deterministic build path

The build tools now use explicit prerequisites and a single selected path.

- Missing Node, pnpm, JDK, Android SDK/platform, or Python fails with the missing prerequisite named.
- The core builder does not download or install toolchains. `scripts/setup-windows.ps1` remains an explicit user-invoked setup utility.
- Network mode is only Direct or a user-supplied Manual proxy. No Windows registry/PAC/proxy probing.
- `pnpm install` runs once with fetch retries disabled.
- Electron packaging runs once; there is no retry, signing-disable degradation, compatibility package, or plain-EXE fallback.
- Android packaging runs once in the explicitly selected daemon or no-daemon mode; it does not clear daemon state, retry, or switch modes after failure.

## What is intentionally not removed

“Simple and deterministic” does not mean deleting product semantics. Workflow migration/future-version protection, autosave restore, undo/redo, execution cancellation/timeouts, SMB protocol timeouts and input validation remain. They preserve user data, define requested behavior, or bound an operation; they do not convert a failed production path into a different path that appears successful.

## Final residue removal

The cleanup also removes the old junction-based `scripts/local-storage.ps1`, the Capacitor junction-path rewrite shim, and the package-manager launcher compatibility helper. Desktop packaging now invokes the project-local TypeScript, Vite and electron-builder entry points directly. Development setup uses an explicit pnpm path and an explicitly invoked Python Runtime provisioning script. These helpers may no longer silently virtualize the source tree or select a different package-manager launcher.
 Android Remote Web likewise uses only the Capacitor `public/` asset root, rather than probing alternate `www`/root layouts. Desktop window presentation no longer has a delayed force-show path, and unused lifecycle/compatibility exports left behind by earlier refactors have been removed.
